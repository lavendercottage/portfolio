# What I have learnt
![Timeline](timeline.png)

### Troubleshooting and Problem Solving

Rather than following a fixed tutorial, I chose to solve each problem as it appeared. Looking back, these challenges became some of the most valuable learning experiences of the project.

### Setting up the development environment

One of the first challenges was simply getting the project running.

I initially explored running Docusaurus locally, but quickly realised that installing and maintaining the required development environment added unnecessary complexity while I was still learning the basics.

Moving the project to GitHub Codespaces provided a cleaner environment, but it also introduced a new workflow and a new set of concepts to understand.

### Learning to work in Codespaces

Working in a cloud-based development environment was unfamiliar.

At first it wasn't always obvious:

* where project files were stored
* how to access the running website
* how the browser preview related to the editor
* when changes had actually been saved

Understanding the relationship between the editor, terminal, browser preview and GitHub repository took some time, but eventually became part of my normal workflow.

### Understanding project structure

Another early challenge was understanding how a Docusaurus project is organised.

Instead of editing pages through a visual interface, I needed to understand folders, Markdown files, configuration files and how they all work together.

Once the structure became clear, creating new pages and organising documentation became much more intuitive.

### Solving problems

Several technical issues appeared throughout the project.
Solving them patiently improved my understanding of how the different tools interact.

### Finding the right working environment

One of the first challenges was finding a development environment that suited my way of working.

I initially started the project using GitHub Codespaces because it provided a ready-to-use cloud environment without requiring a complex local setup. This was a valuable learning experience and helped me understand the relationship between the editor, terminal, repository, and running website.

However, I experienced some challenges with the stability in the cloud environment. Troubleshooting connection issues, rebuilding environments, and managing sessions sometimes became a distraction from the actual documentation work.

I decided to move the project to a local setup using Visual Studio Code and Docusaurus. This gave me a more stable and predictable workflow while still keeping the advantages of Docs-as-Code: writing in Markdown, version control with Git, and publishing through a static site generator.

Finding an environment where I could work efficiently was an important part of the learning process.

### Working with Git

Version control was another completely new concept.

At first I was unsure when to commit changes, what should be committed, and how local work related to the GitHub repository.

As the project progressed, committing changes became a natural habit and helped me work more confidently, knowing I could always return to an earlier version if needed.

### AI as a learning partner

AI played an important role throughout the project—not by writing everything for me, but by helping me understand unfamiliar concepts, troubleshoot errors, explore different approaches, and explain technical terminology.

The experience reinforced the importance of asking good questions, verifying information, and learning by doing.

## Looking Back

The project taught me that troubleshooting is an essential part of learning.

Once I understood how the different tools fit together, the technology itself became much less intimidating.
